# 复变函数全链路修改计划（待确认稿）

日期：2026-10-20。依据[《问题清单与修改手册草稿》](复变函数全链路问题清单与修改手册草稿-20261020.md)逐条定规则。状态：**计划待确认，尚未改任何程序**。

## 背景与范围

全书运行暴露的问题里，有一批是生产程序缺陷：空答复被记成网络失败、纠正包装被当成正文、格式纠正改了判词、中断后无法续做、截图失败占候选、复制后媒体挂载失败等。人工交付和一次性补齐脚本只修了产物，程序没修，重跑还会复现。

本计划只改 `AIforStudy-纯净版` 的生产程序、提示词和测试。**不调 API，不动原 run、补齐副本、人工交付和 ZIP。** 现有全书怎么处理，程序修完后另行决定（用户已定）。

用户本轮已定的选择：

- N：断网时全局暂停，探测（连接＋/models）后原请求重发，不占额度；等待上限 2 小时后暂停；网络正常时同一请求连续 3 次失败才判失败。
- A2：空答复占协议额度重发。
- A6：形状在本地包装，格式纠正里出现的新判词不生效。
- D6：单设 2 次轻量技术修复。
- B7：每张工单可附一条内部说明。
- 补齐脚本不进正式程序。
- 改并发须停下后按交接续跑。
- C3：公共卡改动后自动定向重审。
- 只修程序。

## 逐条规则与改法

每条依次写：规则 → 改法（落点） → 额度 → 最小验收。凡标“已定”的，沿用原规则，只补实现缺口。

### N．网络失败：检测、等待恢复、不占额度（最高优先，用户 2026-10-20 已定）

**现状（已核代码）：**

- 每个逻辑请求只有 2 次传输机会，中间只等 5 秒（`providers/gateway.py:26,283,311-321`）。这 2 次记在账上，resume 也不重置。
- 用完以后：
  - 正文记为 `transport_failed`，resume 时拒绝自动重发（`generation_corrections.py:323-324`），下游一律 blocked。
  - 媒体在调模型前就已登记候选槽（`code_execution.py:323`），失败后被标成 `generation_stopped`，永久停止（:203）。
- 没有任何网络探测和恢复等待。断网期间新派发的请求同样各失败 2 次，失败一路蔓延。

**规则：**

- **N1 网络类失败的范围：** 连接、DNS、TLS 断开、连接或读取超时、读一半断开（IncompleteRead）、HTTP 5xx，即 `http_worker.py` 现在判为 ConnectionError/TimeoutError 的那些。HTTP 429 单列为“限流”。
- **N2 断网即全局暂停：**
  - 任一请求遇到网络类失败，运行中设置一个共享的“网络等待”状态：停止派发新请求，已失败的请求原地等待。
  - 探测按退避间隔进行（10s→30s→60s→…最长每 5 分钟一次）。每次先试 TCP+TLS 连接 API 主机；连通后再 GET `/models` 确认服务可用（不消耗 token）。
  - 探测通过后，用**同一份请求**原样重发，再恢复派发。
- **N3 不占额度：**
  - 网络等待期间的失败与重发，不占传输 2 次、媒体 3 个候选、纠正或返修的任何额度。
  - 媒体沿用原槽位，候选序号不变。
- **N4 请求自身的问题：** 探测显示网络正常（例如 `/models` 通、其他请求也在成功），而同一请求连续 3 次发出后失败（读超时、读一半断开、5xx），才判该请求“传输失败”，并写明原因。这是为了防止同一请求无限重发、反复计费。这 3 次同样不占候选和返修额度。
- **N5 限流 429：** 只让该请求按退避等待后重发，不触发全局暂停，也不占额度；连续限流的重发次数与 N4 共用上限。
- **N6 等待上限：** 连续断网超过 2 小时，整轮安全暂停，状态记为“网络中断暂停”（不是失败），已在途的记录保持可续。网络恢复后 `resume` 继续，所有额度不变。
- **N7 resume：**
  - 已确认是网络类失败的记录（正文纠正日志和媒体槽位），resume 时自动按原请求重发，不占额度。
  - 只有“请求已发出、进程被杀、结果不明”的未知中断，仍按原规则不自动重发并列出，不能借网络规则清零。

**改法（落点）：**

- `providers/gateway.py`：
  - 网络类异常不再走 `for _ in range(used,limit)` 的计数循环，改为进入共享的网络等待。
  - lease 结束时记为 `network_wait`，不计入 `transport_attempts_used`。
  - N4 的“网络正常时同一请求连续失败”单独计数。
- 新增 `providers/network_gate.py`：
  - 运行内共享，包含探测、退避、2 小时上限。
  - runner 派发前先检查它（`pipeline/runner.py:756` 附近）。
  - 每次状态变化写入运行事件：开始断网、每次探测结果、恢复、暂停。
- `pipeline/execution_control.py`：传输计数排除网络等待类记录；账本中保留这些记录，用于统计和审计。
- `blocks/content/generation_corrections.py:336-343,323-324`：
  - 记录真实类别。
  - 网络类失败不触发 `record_failure('transport')` 后的终止；resume 时允许按 N7 重发。
- `blocks/media/code_generation.py:173`、`code_execution.py:203,323,379-414`：
  - 网络类失败不设 `generation_stopped`，原槽位保持“待重发”。
  - 重入时，从该槽位续生成。
- 运行结束状态和报告中，“网络中断暂停”与 failed、partial 分开（见 G1）。

**验收（离线，假传输层）：**

- (a) 前 N 次连接失败、探测恢复后成功 → 产物接收；`transport_attempts_used` 为 0，媒体候选数为 1。
- (b) 断网期间不派发新节点。
- (c) 模拟断网超过上限 → 状态为“网络中断暂停”；resume 后完成，额度不变。
- (d) 探测正常而同一请求连续 3 次读超时 → 该请求判为传输失败，其他请求不受影响。
- (e) 429 不触发全局暂停。
- (f) 正文纠正日志中的 `transport_failed` 记录，resume 时自动重发。
- 用 `IncompleteRead`（http_status=200）、`SSLEOFError` 两种真实异常形态各做一个用例。

### R．字幕与正文渲染修复、最终产物检验（用户 2026-10-20 已定，排在 N 之后；F3 就绪信号提前到本节做）

**现状（只读核实，全书交付版）：**

- 动画字幕是单独的 VTT 轨，由浏览器按纯文本显示（`blocks/render/assets/animations.js:171-183,277-294`）。
  - 548 条字幕里，45 条带 `$`，约 70 条带裸 `^{`/`_{`。
  - 31 条含 `<`，按 VTT 规则会截断后文。这一点是按规范推断的，未经实机验证。
- 生成字幕的提示词（`blocks/media/prompts/code-animation.md:3`）对公式写法没有任何规定。
- `code_runtime.py:220-229` 原样写入 VTT，没有做转义。
- 页面侧的 `captionText()`（`animations.js:69-120`）遇到 Unicode 数学符号会断开，有 65 条显示成半渲染。
- 正文 KaTeX 报错为 0。错误在定界符外的裸 LaTeX：例题标题、批注标题、链接文字、目录标签，例如 `render-core.js:579` 那里只做了 `escapeHtml`。另有一处损坏的链接 `[用相似定理求 L\[sin ωt](...)]`。
- 现有检查不查字幕内容，也不查页面上残留的原始 TeX。最终人工交付版没有跑过浏览器检查。

**规则与改法：**

- **R1 字幕自绘层（用户选 b）：**
  - 播放器把原生字幕轨设为 hidden，自己画一个字幕层，跟着视频时间显示当前字幕，用 KaTeX 渲染公式。
  - 保留 VTT 作纯文本备用：`code_runtime.py` 写入时转义 `<`、`&`。
  - `captionText()` 补上对 Unicode 数学符号（`−`、希腊字母、`∫`、`Σ`、上下标数字）的处理，避免公式被截断。
  - 不重画视频。
- **R2 字幕写法：** `code-animation.md` 规定字幕里的所有数学写在 `$…$` 内，不写裸 TeX。
- **R3 正文标签渲染：**
  - 例题标题、批注标题、链接文字和目录标签，统一走与正文相同的行内公式渲染。
  - 作者提示词规定标题和标签里的数学写在 `$…$` 内。
  - 修好链接文字中方括号的转义。
- **R4 最终产物检验程序（用户定：只出报告，不在阅读界面显示）：**
  - 新增 `./aifs check-render <交付目录>`，用本地 Chromium 打开每个入口（全书和各章），等待就绪信号（即 F3）后逐个单元检查：
    - `.katex-error`；
    - 可见文字里残留的 `$`、`\命令`、`^{`、`_{`；
    - 空正文、缺图、坏图；
    - 每条字幕：VTT 是否转义，自绘层渲染后有没有残留 TeX。
  - 输出一份报告（JSON 加 Markdown），定位到“入口 / 单元 / 字段路径 / 片段”。
  - 不阻止交付，也不改界面。
  - 先在 ZIP 副本上跑一次，作为修改前的基线。
- **验收：**
  - 夹具中带 `$\dfrac{}{}$`、`|z|<δ`、`e^{iθ}` 的字幕，在自绘层中正确渲染，VTT 也不截断。
  - 检验程序对 ZIP 副本报出上面列的已知问题，数量与只读核查一致。修复后，同类问题归零。

### A．API答复与JSON接收

- **A1 网络失败只补失败阶段（已定）。** 由上面的 N 节在程序内实现：网络好了自动续、不占额度。本次补齐方式不做成正式入口（用户定）。
- **A2 空答复。**
  - 规则：可见内容为空且 `finish_reason=stop` 时，归为 `empty_response`，不叫网络失败，也不送语法纠正。
  - 改法：
    - 带提示“上次只有推理没有可见输出，请直接输出完整 JSON”，重发原请求。
    - 落点：`providers/gateway.py:354-369` 区分出空答复；`providers/review_failures.py:10` 增加该类别，同时修掉 `'unparsed'` 被静默改成 `'internal'` 的错。
    - `blocks/content/generation_corrections.py` 把它当作一类纠正处理。
    - `providers/http_worker.py:50-54` 和 `response_evidence.py:16-28` 增加留存 usage（含推理 token）。
  - 额度：占现有协议额度（最多 2 次）。不占 5 次语法纠正，不占媒体 3 个候选。用尽后记“空答复”并停止该项。
  - 验收：
    - 假网关先回空答复、再回正常内容 → 接收，共 1 次重发。
    - 连续空答复 → 状态为 `empty_response`，不是 `transport_failed`。
- **A3 纠正时原样返回坏 JSON。**
  - 规则：仍在 5 次以内，不加次数，不提前终止。
  - 改法：本轮回复的哈希与上一份相同时，下一轮反馈注明“上次返回与原文逐字相同，错误仍在第X行第Y列”。落点：`generation_corrections.py` 语法轮（:286-311）。
  - 验收：原样重复时，第二轮反馈带“未改动”提示。
- **A4 纠正包装被当正文、空正文被接收。**
  - 规则：解析成功之后，程序只做最低限度的可用性检查——是不是该角色要的对象、正文是否非空。这不是结构审核。
  - 改法：
    - (1) 语法纠正回包的顶层如果是纠正请求包装（含 `role_task` / `original_response` / `errors`），算这一轮语法纠正失败，反馈“请只返回修好的完整 JSON”。
    - (2) `blocks/content/json_only.py:107-136` 的 `normalize_author_output`：顶层不是正文对象、或规范化后 `body_markdown` 为空时，报“字段形状错误”。
    - (3) 额度用尽后不接收这一稿，head 保留上一稿及其原审核状态，报告写“返修答复不可用”。
    - (4) 正文为空不发审核，状态记为 missing。
  - 额度：(1) 计语法 5 次；(2) 计协议 2 次。
  - 验收：用双曲函数 000002 的形态构造回放 → 不再产生空正文的 revision，不再出现空正文 verified。
- **A5 四类失败分开。**
  - 规则：
    - 语法不合法 → 语法纠正（5 次）。
    - 合法但形状不对（缺 `verdicts`、正文为空、缺 `code`）→ 协议纠正（2 次）。
    - 空答复 → A2。
    - 长度截断 → 媒体沿用原规则（带提示重试 1 次，计入 3 个候选）；正文按网关已有的截断处理。
    - 真网络/超时 → 按 N 节等待网络恢复后重发，不占额度。
  - 改法：`generation_corrections.py:336-343` 的统一 `transport_failed` 改为按 `ModelCallFailed.failure_kind` 如实记录类别；报告用同一套名称（见 G1）。
  - 验收：每类各一个离线用例，检查记录的类别和扣的额度。
- **A6 格式纠正改了判词。**
  - 规则：格式纠正不能改变实质判词。
  - 改法：
    - `blocks/content/review.py:437-461`：顶层是裸数组且每行都是判词时，由程序本地包成 `{verdicts}`，不调模型。
    - 确需模型纠正格式时，只取被指出的坏行的修正版；状态有变化或新增的行，记成 `format_correction_drift` 留证，不生效。
    - 修掉 :457-458 把所有轮次的行累加进结果的做法。
  - 额度：只计格式额度。
  - 验收：回放 CH01-S01-SS04 的 000005（数组、pass）→ 直接 pass，0 次纠正调用。构造“纠正中把 pass 改成 fail”的用例 → 保留原判，有漂移记录。

### B．模型审核与正文返修

- **B1 有明确 action 的疑点没返修（已定）。**
  - 改法：`blocks/media/code_execution.py` 重入时的两处提前返回（:215-219、:277-280）改为：如果存在 `include_needs_review=True` 的可执行疑点，且这项媒体还没做过疑点返修，且候选未满 3，就进入返修，反馈用 `_feedback(include_needs_review=True)`。
  - 额度：占原 3 个候选，每项媒体最多 1 次。
  - 验收：既有的离线探针 `test_rules_recovery_probe.py` 第二项（制作调用应为 2 次）通过。
- **B2 判词与冻结输入不符、新旧问题混淆。**
  - 只改提示词和审核材料，不加逐字比对拦截（这是已冻结的机械门 #2）。
  - 审核材料里，`source_excerpt` 标明“教材原文，可能含 OCR 旧字，不是卡片现值”；提示词要求：
    - 引用卡片内容以 `concept_index` 当前值为准。
