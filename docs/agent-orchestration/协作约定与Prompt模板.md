# 协作约定与 Prompt 模板

## 角色与推进方式

用户提供目标、想法和偏好；主 Agent 负责结合当前代码补全需求、划定范围、组织执行、审查结果和管理 Git。用户不需要先写技术方案。

讨论想法或要求写 Prompt 时，交付完整任务说明；用户明确要求实施时，直接在已授权范围派发，不重复申请同一项授权。调研结果不自动授权实现其全部建议。

每轮依次完成：

1. **还原意图**：描述谁在什么情境遇到什么问题、完成后有什么变化。
2. **核对现状**：锁定仓库/分支/提交和真实入口，复用项目资料，区分已有、需改、需新增。
3. **补全需求**：写清流程、数据、边界、失败处理和验收；明确哪些是用户要求、合理推定或待决定项。仅追问无法从资料推断且会改变方向的关键问题。
4. **形成 Prompt**：给出可独立转交的完整文本，包含实际路径与上下文，不让执行 Agent 猜上一段聊天。
5. **组织执行**：有实施指令后按独立模块分派；同一文件只安排一个写入负责人，依赖顺序明确。
6. **独立复核**：检查目标行为、真实证据和副作用；指出未覆盖项，再完成提交和交接。

## 每轮主任务 Prompt

发送前必须用当前任务事实填满下列方括号；不适用项写明原因，不能把空模板当成完整交付。

```text
你是 AIforStudy 项目的 [角色]。

一、工作基线
- 仓库绝对路径：[实际路径]
- 当前分支与提交：[本轮核对结果]
- 主版本：2026-11-15 交接演进线；当前仓库根就是 AIforStudy。
- 先读：[本轮相关现状文档、规格、入口、契约、测试的具体路径]
- Git：先检查状态；保留既有改动；使用 codex/任务名 分支或已指定分支。

二、用户目标
- 用户原意：[忠实概述]
- 使用者与场景：[谁、何时、当前障碍]
- 预期体验：[一个具体的使用前后例子]
- 本轮任务类型：[只读调研 / 方案与Prompt / 实施 / 复核 / 部署]

三、当前事实
- 已有能力与复用位置：[具体文件、入口、数据结构]
- 当前差距：[可观察现象及证据]
- 已知限制：[环境、模型、资料或兼容约束]
- 不确定项：[尚未验证的事实，及如何验证]

四、范围与需求
- 本轮必须完成：[按用户流程描述的具体要求]
- 本轮不涉及：[明确边界，避免连带重写]
- 正常流程：[输入→操作→结果→保存/回看]
- 边界流程：[首次使用、空内容、取消、错误、恢复、重复操作]
- 数据约定：[来源、ID、版本、存储、锚点、接口及迁移]
- 兼容要求：[原有教材/历史运行/桌面或移动等与本任务有关的要求]
- 用户已确定的约束：[只列本轮相关要求]
- 合理假设：[说明依据；重大产品决定不能冒充用户已确认]

五、执行方式
- 主负责人：[模块及拥有的文件]
- 并行子任务：[Agent、目标、可改范围、输入、交付物]
- 依赖关系：[谁先完成契约，谁消费结果]
- 公共文件：[唯一写入负责人]
- 无需实现的研究方向不得顺手落地。
- 不重复下载、调用模型或重做已验证产物；确需真实调用时按本轮范围和配置执行。

六、验收标准
- 行为验收：[可复现步骤、输入、预期输出]
- 内容/来源验收：[与用户教材及具体来源如何对照]
- 页面/媒体验收：[实际查看、播放、交互，不只检查文件存在]
- 回归范围：[具体测试与选择理由，明确离线/受控/真实调用]
- 失败与恢复验收：[本轮涉及的中断、版本冲突、缺资源情形]
- 通过条件：[分别说明实现、工程验证、真实业务验证]

七、交付格式
1. 改了什么、为什么、涉及哪些文件。
2. 验证命令、实际结果和证据位置。
3. 未完成/未验证项及原因，不用成功退出码代替质量结论。
4. Git 分支、提交号、剩余改动和必要的恢复说明。
5. 主 Agent 可直接复核的总结；需要决策时先把具体选项与影响整理好。
```

## 子 Agent 任务书

每个子 Agent 只接收完成其任务所需的独立上下文：目标、基线、必读文件、文件所有权、不可改范围、输入输出契约、验收及返回格式。读代码和独立复核可并行；共享契约先定再实现，不能让多个 Agent 同时改同一文件后碰运气合并。

建议角色按任务复杂度选用：需求/架构核对、具体模块实现、独立审查。小任务无需凑齐所有角色；主 Agent 对最终结果负责。

## 本项目的验收提醒

- 教材生产状态、工程测试通过、实际教学正确性是不同结论，逐项报告。
- 正文、来源、媒体或视频修订改变后，更新相应身份和证据；不得仅改哈希、沿用旧通过状态。
- 当前 balanced 的 `scope_accepted` 不等于完整发布认证；以本轮明确验收为准。
- 原位问答若获实施授权，重点验证教材与个人答案分离、固定版本、精确锚点、阅读位置和单步继续的幂等性；研究中的验收建议要按本轮方案重新落实。
- Linux 运行、移动端真机、配音听感、全新 PDF 冷启动等未验证事项不能因既有 Mac 成品而写成通过。

## Git 约定

开始先记录状态与基线；按目标建立 `codex/` 分支，小步提交可解释的变更。保存用户原改动，不混入凭据、环境、缓存和生成视频；忽略规则不能误排除真正的源码。提交前核对暂存 diff 和相关验证证据。

本轮建立的旧开发树快照是保全点，不是稳定发行版。推送、合并和上线按具体任务授权执行；本地提交不会自动更新线上网站。
